## Findings
- Source observation: `scripts/restore-postgres.ps1` runs `dropdb --if-exists --force $TargetDatabase` after archive-list validation and before `createdb`; later validation failure runs another `dropdb` because `$targetCreated` is true. A valid archive missing the sentinel therefore destroys a pre-existing target and then removes its replacement.
- RED invocation: `pwsh -NoProfile -File scripts/test-restore-safety.ps1` against project `tolikrestorec62fe1f88cf2454b84c38f198fd9834e`; exit 1 with verbatim observable `Existing target database was dropped; observed count '0'.` The missing-sentinel archive passed `pg_restore --list` and reached post-restore sentinel validation in the old implementation. Artifact: `.omo/evidence/restore-safety-red.txt`.
- Root cause confirmed: toggling the unconditional pre-restore `dropdb` into a fail-closed `pg_database` existence guard changes the same harness from database count `0` to `PASS existing target rejected and guard row preserved`.
- GREEN invocation: `pwsh -NoProfile -File scripts/test-restore-safety.ps1` against project `tolikrestorea110ee5ba43c4084964cd0daac9887f5`; exit 0. Verbatim observables: `PASS existing target rejected and guard row preserved`, `Restore validated: database=fresh_target migrations=1 sentinel=backup_sentinel`, `PASS fresh target restored with migration and sentinel`, and `PASS corrupt archive rejected before target creation`. Artifact: `.omo/evidence/restore-safety-green.txt`.
- Cleanup invocation: Docker label inventory for project `tolikrestorea110ee5ba43c4084964cd0daac9887f5` plus temp-directory inventory; exit 0 with `containers=0 volumes=0 networks=0 tempDirectories=0`. Artifact: `.omo/evidence/restore-safety-cleanup.txt`.

## Final fix
- `scripts/restore-postgres.ps1`: validates the archive, queries `pg_database`, rejects an existing target, and sets rollback ownership only after `createdb` succeeds. Native command exit codes are captured before output normalization.
- `scripts/test-restore-safety.ps1`: isolated real-PostgreSQL RED/GREEN regression covering existing data, successful fresh restore, corrupt input, and teardown.
- `README.md`: documents that restore requires a new database name and refuses existing targets without mutation.
