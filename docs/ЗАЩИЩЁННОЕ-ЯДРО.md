# Защищённое ядро — что TOLIK не имеет права менять сам

Документ отвечает на один вопрос: **какие файлы TOLIK не может изменять
самостоятельно, даже если владелец попросил, и что нужно, чтобы это стало
технически невозможным, а не просто записанным в документе.**

Решение владельца (05.11.2026): список нужен.

Сейчас это **декларация**. Проверка в коде — задача 5.2 в
`docs/ПЛАН-ЭТАЛОН.md`. До её выполнения документ описывает намерение, а не
свойство системы; выдавать одно за другое нельзя.

## Почему это вообще нужно

Способность TOLIK улучшать собственный код — цель проекта. Но она же создаёт
замкнутый круг: если TOLIK может править свою авторизацию, то любая его
ошибка, любое повреждение промпта или инъекция в прочитанном документе
превращаются в отключение всех ограничений. Правило простое: **система,
которая проверяет разрешения, не может переписывать саму проверку без человека
в контуре.**

Это не недоверие к TOLIK. Это та же причина, по которой в банке нельзя выдать
себе доступ, даже будучи сотрудником.

## Список

### Уровень 1 — запрещено полностью

TOLIK не изменяет эти файлы ни при каких обстоятельствах. Только человек,
только вручную, только с ревью.

| Путь | Что там | Почему |
|---|---|---|
| `src/TOLIK.Infrastructure/Authorization/AuthorizationPolicy.cs` | Решение allow/deny по риску | Правка = отключение всех ограничений |
| `src/TOLIK.Infrastructure/Authorization/ConfirmationStore.cs` | Подтверждения и их привязка к действию | Правка = обход подтверждений |
| `src/TOLIK.Infrastructure/Authorization/PathIsolationPolicy.cs` | Запрет на чувствительные пути | Правка = доступ к секретам |
| `src/TOLIK.Infrastructure/Authorization/CapabilityBoundaries.cs` | Границы возможностей | Правка = расширение своих прав |
| `src/TOLIK.Infrastructure/Authorization/CoreSecurityState.cs` | Состояние LOCKED | Правка = снятие блокировки |
| `src/TOLIK.Infrastructure/Authorization/EmergencyStopState.cs` | Аварийная остановка | Правка = невозможность остановить |
| `src/TOLIK.Infrastructure/Identity/IdentityService.cs` | Роли, MFA, enrollment | Правка = выдача себе роли Owner |
| `src/TOLIK.Infrastructure/Identity/TolikRoles.cs` | Потолки ролей | Правка = повышение прав |
| `src/TOLIK.Infrastructure/Identity/DeviceChallengeVerifier.cs` | Проверка подписи устройства | Правка = подделка аутентификации |
| `src/TOLIK.Infrastructure/Identity/IdentityKeyHierarchy.cs` | Иерархия ключей | Правка = компрометация идентичности |
| `src/TOLIK.Infrastructure/Auditing/**` | Цепочка аудита и её хеши | Правка = заметание следов |
| `src/TOLIK.Contracts/CapabilityRegistry.cs` | Риск-уровни всех возможностей | Правка = понижение риска до LowRisk и обход подтверждений |
| `AGENTS.md` | Архитектурные правила | Правка = переписывание себе правил |
| `SECURITY.md`, `docs/SECURITY.md` | Модель безопасности | То же |
| `docs/governance.md` | Правила управления | То же |
| `.env`, `.env.*` | Секреты | Прямой доступ к секретам |

### Уровень 2 — только с явным подтверждением владельца

TOLIK может предложить изменение и подготовить его, но применить — только после
подтверждения человеком с MFA. Уже частично работает: такие пути эскалируются
до `Critical` в `AuthorizationPolicy` (изменение security-critical source).

| Путь | Почему не полный запрет |
|---|---|
| `src/TOLIK.Infrastructure/Persistence/Migrations/**` | Схема должна развиваться, но молчаливая миграция может уничтожить память |
| `src/TOLIK.Core.Host/Program.cs` | Здесь границы API и точка диспетчеризации; правки нужны, но опасны |
| `src/TOLIK.Infrastructure/Genesis/**` | Церемония необратима |
| `src/TOLIK.Infrastructure/Authorization/AgentTransportAuthorization.cs` | Граница доверия к Agent |
| `src/TOLIK.Infrastructure/Transport/**` | Подписанный транспорт и защита от повторов |
| `scripts/backup-postgres.ps1`, `scripts/restore-*` | Без бэкапа нет отката |
| `docker-compose.yml`, `Dockerfile` | Молчаливое изменение окружения меняет всю модель угроз |

### Уровень 3 — свободно

Всё остальное: клиенты, голос, цефалон, документы, тесты, обычные сервисы.
Здесь TOLIK работает самостоятельно, с обычными риск-уровнями.

## Как это станет настоящим ограничением

Документ сам по себе ничего не запрещает. Задача 5.2 требует:

1. **Детерминированная проверка пути.** Перед записью файла путь сверяется со
   списком; попадание в уровень 1 → отказ, в уровень 2 → эскалация до
   `Critical`. Не через LLM — обычной функцией, как `PathIsolationPolicy`.
2. **Тест, который не даёт списку исчезнуть.** Тест проверяет, что каждый путь
   из списка существует и что попытка записи в него отвергается.
3. **Защита от изменения самого списка.** Список — часть уровня 1. Иначе
   первый же удачный ход TOLIK его отредактирует.
4. **Отдельный аудит.** Любая попытка записи в уровень 1 пишет событие
   `SECURITY` с указанием, кто и что пытался сделать.

Пока эти четыре пункта не сделаны, ограничение держится только на дисциплине
и на том, что TOLIK сейчас не запускает правки сам.

## Чего здесь нет

Списка «доверенных» путей, которые можно менять без проверок. Доверие к пути —
это дыра: сегодня безопасный файл завтра становится точкой входа. Проверка
идёт по запрещённому, а не по разрешённому, — так ошибаться безопаснее.
