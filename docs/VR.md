# TOLIK VR — Meta Quest 3S (стратегия, 05.10.2026)

Продолжение экосистемы, не вариация: TOLIK крутится на домашнем ПК, работает там же;
шлем — thin-клиент с удалённым доступом (как Android-клиент из плана), но с
passthrough и объёмным цефалоном.

## 1. Суть

Пользователь получает приложение с passthrough, которое выводит в окружающее
пространство интерактивного цефалона в объёме. Суть цефалона та же, что в Android-
версии и в Desktop: состояния, голос, привязка к настоящему TOLIK. По итогу:

- **виртуальный монитор** с программой, с которой ведётся работа (окно OpenCode с ПК);
- **проекционная клавиатура** шлема (встроенная, системная);
- вокруг **летает и разговаривает цефалон TOLIK**, привязанный к настоящему TOLIK;
- **подключение по QR-коду**, разово сканируемому на шлеме — всё привязывается.

## 2. Принятые решения (владелец, 05.10.2026)

1. **Граница безопасности — плагин-мост: OpenCode → Core → шлем.** Плагин интегрирует
   события сессии OpenCode в TOLIK Core; шлем подключается ТОЛЬКО к Core (QR выдаёт
   Core). Авторизация и ревокация остаются в Core — SECURITY-модель не ослабляется
   (§1: только Core решает, что разрешено).
2. **Монитор — стрим окна OpenCode с ПК.** Видео-стрим одного окна (не весь desktop —
   least privilege §5), рендерится на виртуальном мониторе в шлеме.
3. **Стек — Unity + Meta XR SDK.** C# совпадает со стеком TOLIK (§4.1); де-факто
   стандарт для Quest; passthrough, keyboard tracking, пространственный звук из коробки.
4. **Клавиатура — встроенная проекционная (системная) клавиатура шлема.** Без
   кастомной клавиатуры в v1.
5. **Порядок — после Desktop Phase 1 (M9-M13).** Дизайн-система цефалона из Desktop
   переносится в VR как 3D-продолжение (один дизайн-источник: cephalon.html reference).

## 3. Архитектура

```text
Домашний ПК (настоящий TOLIK)
├── TOLIK Core (.NET 10)
│     ├── Identity / Authorization (единственная авторизация — §1)
│     ├── Device Registry (шлем = устройство, ревокуемое §10/§11)
│     ├── Voice pipeline (STT/VAD/TTS — M4/M5/M6)
│     └── RealtimeEventHub (существующий WS: состояния для клиентов)
├── OpenCode plugin (мост: события сессии OpenCode → Core, authenticated)
│     └── НЕ exposes OpenCode напрямую шлему — граница в Core
└── Windows Agent
      ├── run_opencode (существующий: процесс, stdin/stdout, отмена §39)
      └── НОВОЕ: capture_opencode_window (видео-стрим окна, READ_ONLY)

Meta Quest 3S (Unity + Meta XR SDK — thin-клиент)
├── Passthrough
├── Цефалон в объёме (3D: idle/speaking/working/alert — от RealtimeEventHub)
├── Виртуальный монитор (стрим окна OpenCode, латентность цель <100ms LAN)
├── Проекционная клавиатура (системная; ввод → Core → агент → stdin OpenCode)
└── TTS (цефон говорит; пространственный звук Meta SDK; позже — mic → STT/VAD)
```

## 4. Паринг по QR (разово, «всё привязывается»)

```text
1. Пользователь запускает приложение TOLIK на шлеме
2. Приложение: «отсканируй QR»
3. Пользователь инициирует паринг (Desktop UI / Core API):
   QR = Core URL + одноразовый код (TTL 5 мин, single-use, audited)
4. Шлем сканирует → POST /auth/pair → Core проверяет код → выдаёт DEVICE identity:
   криптографическая identity устройства (§11), ревокуемая независимо от файлов;
   копирование приложения не клонирует identity
5. Всё привязывается: шлем = устройство в реестре Core. Least privilege (§5):
   чтение состояний + голос + стрим отслеживаемого окна + ввод клавиатуры.
   НЕ: shell, файлы, destructive, авторизация других устройств.
6. Ревокация: Core отзывает шлем в любой момент (§10). Tailscale ≠ авторизация (§37).
```

Паринг переиспользует существующий паттерн owner-issued enrollment tokens
(POST /auth/enrollment-token, single-use, TTL 10 мин, audited — Track 1) — новый
эндпоинт /auth/pair для устройств.

## 5. OpenCode plugin (мост)

Назначение: события сессии OpenCode (задача запущена/прогресс/инструмент/завершена)
→ TOLIK Core (authenticated) → RealtimeEventHub → цефалон + Desktop + VR. Плагин даёт
цефалону «знание о кодинге» (working-состояние с реальным прогрессом) и не открывает
OpenCode наружу.

Требования перед реализацией:
- Инспекция установленной версии OpenCode и его plugin API (§9: никогда не выдумывать
  флаги/API). Плагин — hooks OpenCode на стороне ПК.
- Аутентификация: плагин использует Device credentials (не LLM, не сессию пользователя).
- События в Core — без приватного содержимого (пути/тексты — как в аудите §38).

## 6. Виртуальный монитор (стрим окна)

- Захват: Windows Agent, Windows.Graphics.Capture (окно OpenCode TUI) — READ_ONLY
  capability, разрешение владельца, ревокуемо.
- Энкод: H.264 (аппаратный) → relay через Core → шлем.
- Политика приватности (§50): содержимое окна — приватные данные владельца; только
  ОДНО окно; включение/выключение стрима — разрешение + индикатор.
- Латентность LAN: измерить (цель <100ms); 1080p H.264 ~2-5 Mbit/s — приемлемо.

## 7. Фазы (после Desktop Phase 1)

```text
VR0 — recon: Unity + Meta XR SDK окружение, шлем; инспекция OpenCode plugin API (§9)
VR1 — паринг: Core /auth/pair + QR + Device Registry; шлем: скан → bind → authenticated WS
VR2 — цефалон в объёме: passthrough + 3D-цефон + состояния от RealtimeEventHub
      (перенос дизайн-системы Desktop M10-M13 в 3D; speaking = audio amplitude → eye pulse)
VR3 — виртуальный монитор: capture_opencode_window (агент) → Core relay → шлем; замер латентности
VR4 — ввод: проекционная клавиатура → Core → агент → stdin OpenCode
      (MODIFY-класс: ввод в работающий процесс — сессия/подтверждение, аудирование)
VR5 — голос: TTS (цефон говорит) + пространственный звук; позже — mic → Core STT/VAD
      (как Android: голос через существующий пайплайн M4/M5/M6)
VR6 — polish: comfort, FPS 72/90, батарея, spatial audio
```

## 8. Смарт-очки (будущее: Ray-Ban Meta / Xiaomi) — проверено 05.10.2026

**Meta открыла платформу** (актуально на 05.10.2026):

- **Web Apps на Ray-Ban Display**: стандартные HTML/CSS/JS прямо на очках (дисплей
  600×600 additive, деплой по URL), добавляются **сканированием QR-кода** → deeplink →
  Meta AI app → очки. Ровно ментальная модель владельца (QR + привязка). Тот же
  цефалон-минимализм: состояния + голос через `speechSynthesis` (динамик очков,
  без permission prompt).
- **Meta Wearables Device Access Toolkit 1.0** (стабилен с 30.09.2026): мобильный SDK
  (Swift/Kotlin) — камера, аудио, микрофон, дисплей-компоненты, video streaming;
  покрывает Ray-Ban Meta Gen 1/2, Ray-Ban Meta Display, Oakley Meta HSTN/Vanguard.
  Путь TOLIK: голосовой ввод (мик) + camera → perception coordinator — расширение
  Android-клиента.
- **Meta AI Connectors**: подключение сервиса напрямую к Meta AI (API → tools) —
  альтернативный путь для голосовых сценариев без своего приложения.

**Путь TOLIK для очков (после VR-трека):**
1. Web App (QR-добавление): состояния цефалона + TTS-ответы — минимальный путь,
   HTML/CSS/JS, быстрая итерация.
2. Device Access Toolkit (расширение Android-клиента): мик → STT/VAD + камера →
   Perception — полноценное голосовое взаимодействие.

**Xiaomi / другие Android-очки:** вне портфеля Meta — путь: тот же thin-клиент
(стандартный Android), audio + camera. Требует research при подходе к фазе.

## 9. Безопасность (чек-лист §28 для каждой фазы)

1. Что trusts? — Core (единственная авторизация); шлем/плагин — untrusted до auth.
2. Кто может invoke? — устройства с device credentials; least privilege §5.
3. Какие данные? — состояния/голос/окно OpenCode (приватные §50, ревокуемо).
4. Что при compromised? — ревокация устройства → LOCKED-состояние шлема (§27,
   non-destructive).
5. Как ревокация? — Device Registry Core (§10/§11), независимо от файлов.
6. Как audited? — паринг/стрим/ввод — аудит-события (§38).
7. Как fails? — fail-closed (§14): unknown device → deny.
