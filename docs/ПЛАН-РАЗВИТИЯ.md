# TOLIK — рабочий план на русском языке

## Принципы

1. Core остаётся authority и не передаёт LLM unrestricted shell.
2. Client, Core и Agent развиваются отдельно.
3. PostgreSQL является каноническим хранилищем.
4. Любая capability имеет risk level, allowlist, audit и cancellation.
5. Секреты живут только в runtime configuration.

## Routing моделей

`gpt-6-astra` назначается главным оркестратором: декомпозиция задач, выбор роли, контроль безопасности и финальная агрегация.

Роли задаются конфигурацией, а не кодом:

- сложное reasoning/архитектура: `gpt-6-astra`;
- обычная реализация и рефакторинг: `gpt-5.6-terra`;
- быстрые небольшие задачи и классификация: `gpt-5.6-luna`;
- сложный coding/review: `gpt-5.6-sol`;
- vision: `gpt-image-2.5` или доступный vision-capable provider;
- дешёвые вспомогательные проверки: `gpt-5.4-mini`, `gemini-3.5-flash`, `claude-haiku-4-5` или аналог после live проверки.

До фактического запроса каждая модель имеет статус `Unverified`. Router должен проверять timeout, quota, provider failure и отсутствие credentials.

## Результат проверки провайдера

- Провайдер: `https://dindindon.ru/v1` из текущего `.codex/config.toml`.
- Переменная ключа присутствует в окружении; значение намеренно не записывается.
- `GET /v1/models`: HTTP 200, доступно 45 моделей.
- Минимальный chat probe на `gpt-6-astra`: HTTP 200, ответ получен, latency около 12.3 секунды.
- `gpt-6-astra` можно назначить главным оркестратором; это уже совпадает с текущей настройкой Codex.
- Возможности и цены не считаются подтверждёнными одним списком моделей: нужен отдельный измерительный прогон и тарифные данные провайдера.

## Обновлённая политика стоимости и делегирования

По реальному трафику 19.09.2026 один запрос Astra с контекстом около 260K входных токенов стоил примерно 54–65 кредитов, а запрос без cache read достигал примерно 488–523 кредитов. Полный контекст нельзя пересылать Astra на каждом шаге.

1. Astra остаётся главным оркестратором, но получает краткий task brief, состояние, diff и результаты подагентов. История сначала сжимается.
2. Простые проверки направляются в `gpt-5.6-luna`, `deepseek-v4-flash-0731`, `glm-5.3-flash` или `hy3`.
3. Обычная разработка направляется в `gpt-5.6-terra`; сложный coding/review — в `gpt-5.6-sol`. Astra нужна для архитектуры и финального конфликта.
4. Экономичный пул: `deepseek-v4-flash-0731`, `glm-5.3-flash`, `hy3`, `minimax-m3`.
5. `gpt-5.4-mini` не использовать до исправления доступности: текущий статус 0%.
6. Не использовать обычно: `grok-4.6` (7.95%), `mimo-v2.5-pro` (75%), `gemini-3.6-flash` (67.92%), `gemini-3.5-flash` (84.34%).
7. Vision направлять в `deepseek-v4-flash-vision-exp` или image-модель по типу операции.
8. Ввести budget class: `economy`, `standard`, `reasoning`, `critical`. Только `critical` может эскалировать в Astra, с явной причиной.

Стоимость контекста считать отдельно от стоимости вывода. Для длинных задач сначала отправлять summary/diff, а не всю историю.

### Применённая конфигурация (2026-09-19)

Маршруты TOLIK заданы в `src/TOLIK.Core.Host/appsettings.json` и зарегистрированы в DI host. `SIMPLE` использует `deepseek-v4-flash-0731`, `REASONING` — `gpt-6-astra`, `CODING` — `gpt-5.6-sol`, `VISION` — `deepseek-v4-flash-vision-exp`. Astra остаётся основным оркестратором и финальным проверяющим.

Ключи не хранятся в репозитории: для запуска применяются переменные `TOLIK_MODELS_<ROLE>__API_KEY` или существующий секрет провайдера через окружение. Проверка после настройки: `dotnet build TOLIK.sln --no-restore` без предупреждений и ошибок; `dotnet test TOLIK.sln --no-build` — 47/47.
