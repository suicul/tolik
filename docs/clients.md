# Клиенты TOLIK — иерархия и границы

> Решение владельца, 03.11.2026. Этот документ — источник истины по вопросу
> «какой клиент главный». Он старше любых ранних заметок, где Android назывался
> «основным голосовым интерфейсом».

## 1. Иерархия

| Приоритет | Платформа | Роль | Состояние |
| --- | --- | --- | --- |
| 1 | **Windows** | **Целевая платформа и главный клиент.** Здесь владелец работает, разговаривает с Толиком и получает полный набор возможностей. | Панель присутствия (цефалон) работает; чат и микрофон отсутствуют |
| 2 | **Android** | **Продолжение системы, карманный инструмент.** Не копия Windows-клиента: другой сценарий — быстрый доступ и голос вне дома. | Чат, голос, цефалон, уведомления работают |
| 3 | **Linux** | Тонкий аутентифицированный клиент. Не содержит Core, памяти, ключей и тяжёлых моделей. | CLI: bootstrap и отправка запросов |
| — | **Web** | **Только референс цефалона для разработки.** В продукте не требуется. | `src/TOLIK.Core.Host/wwwroot` |

Android — не «версия Windows для телефона» и не урезанная копия. Это отдельная
точка присутствия той же личности: то же ядро, та же память, та же история,
но свой пользовательский сценарий. Windows остаётся местом, где система
проектируется, отлаживается и используется полноценно.

## 2. Что это меняет по сравнению с ранними документами

Ранние материалы (`docs/android-app.md`, презентация, сводное описание) называют
Android «одним из главных будущих интерфейсов» и «перспективой стать основным
голосовым интерфейсом». Это формулировки периода, когда Windows-клиент ещё не
был спроектирован.

Актуальная иерархия:

- Windows — целевая платформа; полнота функций принадлежит ей.
- Android — продолжение; его задача — присутствие вне дома, а не замена ПК.
- Отсутствие функции в Windows-клиенте — это **дефект главного клиента**,
  а не «пока не сделали».

## 3. Границы, общие для всех клиентов

Ни один клиент не является источником полномочий. Клиент:

- не авторизует действия;
- не владеет памятью;
- не назначает Agent;
- не меняет lifecycle;
- не содержит секретов Core.

Клиент получает сессию от Core, передаёт ввод, отображает состояние и
подтверждения. Решение о допустимости действия принимает только Core
(`AGENTS.md`, «SECURITY & TRUST MODEL», §1–§4).

Веб-страница нарушала это правило: `wwwroot/policy.js` и `wwwroot/secrets.js`
содержали вторую реализацию правил доступа на клиенте. Поэтому она объявлена
референсом, а не продуктом — и 03.11.2026 удалена из продукта. Копия протокола
остаётся в `interface/` как материал для чтения, Core её больше не раздаёт.

## 4. Что считается готовностью Windows-клиента

Главный клиент обязан уметь то, ради чего система существует:

1. Текстовый чат с Core (`POST /chat`). — **есть с 03.11.2026** (`ChatWindow`, CE-5)
2. Голосовой ввод с микрофона ПК: захват → `POST /voice/turn-stream` →
   воспроизведение поточного аудио. — **есть с 03.11.2026** (`VoiceTurnClient`)
3. Отображение состояния (цефалон) — есть с CE-1…CE-4.
4. Показ подтверждений для рискованных действий. — **отсутствует**: Core
   возвращает запрос подтверждения текстом, отдельного UI подтверждения нет.
5. Индикация деградации: Core недоступен, модель недоступна, идёт запись. — есть:
   состояние связи в шапке, «слушаю…», отдельные строки-уведомления об отказах.

Что клиент **не** делает (и не должен): не авторизует, не хранит память, не
решает, какое действие разрешено, не содержит секретов. Голосовая дорожка это
подтверждает: запись и воспроизведение — на клиенте, распознавание, определение
говорящего, память и синтез — в Core и Voice-сервисе.

### Проверка голосового пути без микрофона

`tools/VoiceProbe` (вне solution) прогоняет тот же транспорт клиента против
живого стека и печатает статус, распознанный текст, число аудиофрагментов и
тайминги:

```powershell
dotnet run --project tools\VoiceProbe -- <путь-к-16кГц-моно-wav>
```

Живой прогон 03.11.2026: `status: Ok`, 31 текстовая дельта, 2 аудиофрагмента
(346 КБ речи), первый текст 14.7 с, первое аудио 19.0 с, всего 22.9 с.

## 5. Голос на Windows

Микрофон — микрофон ПК (решение владельца, 03.11.2026). Android-микрофон
остаётся для сценария «вне дома», но не заменяет ПК.

Целевой поток остаётся общим для всех платформ (`AGENTS.md` §14, §24):
захват → VAD → STT → определение говорящего → намерение → Core → ответ → TTS.
Различие только в том, где выполняется захват и воспроизведение.
