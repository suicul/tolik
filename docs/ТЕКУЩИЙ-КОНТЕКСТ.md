# TOLIK — текущий контекст разработки

Дата фиксации: 02 октября 2026 года

## Где находится проект

Проект уже прошёл стадию первоначального каркаса. В решении есть отдельные проекты `TOLIK.Contracts`, `TOLIK.Core`, `TOLIK.Infrastructure`, `TOLIK.Core.Host`, `TOLIK.Agent`, CLI-клиент и заготовка Android-клиента. Core и Agent разделены процессно и общаются через контракты.

Git-репозиторий инициализирован (ветка `master`, история с PRE-GENESIS baseline); состояние определяется исходниками, документацией, миграциями и тестами — источник истины: 232/232 теста зелёные (02.10.2026).

## Уже реализовано в коде (актуализация 02.10.2026)

- Всё перечисленное ниже из фиксации 23.09 остаётся в силе. Сверх того добавлено
  (каждый пункт с тестами, полный прогон 232/232 зелёный):
- MemoryOrigin: `tolik_memories.Origin` (lived default, миграция применена к live DB),
  `MemoryOrigin.Normalize` (bad origin → 400), ADR-001 backfill.
- Command-surface denylist: `CommandArgumentPolicy` (command/shell/exec/argv/script/eval
  запрещены в `CommandRequest.Validate` + `AgentTransportAuthorization.Evaluate`).
- Strict JSON envelope: глобальный `UnmappedMemberHandling.Disallow` — неизвестные поля
  → auto-400 на всех POST DTO.
- Typed roles + ceilings (T15): `TolikRoles` — strict parse, Owner→Critical,
  AuthorizedUser→Destructive, Family→Modify, TrustedGuest→LowRisk, Guest→deny;
  capability minimum-role matrix (RunCodex/RunOpenCode/RunProcess→Owner, WriteFile→Family).
- Authorization lease (TTL 60s + offline read-only cap): `AuthorizationLeaseStore`,
  wired в `/tasks/{id}/execute` DispatchGuardedAsync.
- LOCKED state (§27): `CoreSecurityState`, brute-force trip-wire (10 неудач → LOCKED,
  auth отказан для всех), owner-контроль `POST /security/lock` / `POST /security/unlock`
  (out-of-band unlock code).
- §18 trusted-person enrollment: owner-issued single-use токены (`POST /auth/enrollment-token`
  → `POST /auth/enroll`), роль Family/TrustedGuest, scoping проверен тестами.
- Model ask-policy: `ModelPreferenceStore` + `POST/GET/DELETE /models/preference` +
  `ResolveWithFallback(kind, preference)` (Local → offline-first coding).
- Transport primitives (part 1): `SignedTransport`/`NonceStore`/`PeerRegistry` —
  подписанные фреймы ES256 + replay-защита; wiring в agent-протокол — part 2 (VPS-prep).
- Sanitization (§22/T11): `ModelResponseSanitizer` — instruction-shaped строки
  вырезаются из ответов модели до отображения/озвучки/памяти; wired в /chat + /voice/turn.

- ASP.NET Core host с health/status API и authenticated API boundary.
- PostgreSQL/EF Core persistence, identity bootstrap, device/session lifecycle и revoke.
- Authorization policy с capability/risk уровнями, confirmation-путём и audit logging.
- Agent registration и ограниченный dispatcher без unrestricted shell API.
- Task lifecycle, bounded planner и ограниченный execution path.
- Безопасное отключение Agent: authenticated `POST /agents/{agentId}/disconnect`, ownership audit, атомарное удаление connection/queue и отмена pending command completions; reconnect создаёт новую очередь.
- C# LSP project configuration очищена от неподдерживаемого `solutionPathOverride`; добавлен симметричный `.opencode/lsp.json` для `csharp-ls`. Сервер установлен, но диагностика файлов из подкаталогов может оставаться неполной без запуска LSP из корня solution.
- Agent poll/complete теперь связывают ownership с чтением очереди и завершением команды под единым `connectionGate`, поэтому переподключение другого владельца не создаёт TOCTOU-доступ к старой команде.
- Task execution cancellation теперь сохраняет `Cancelled` в PostgreSQL и для task-token cancellation, и для отмены HTTP-запроса; in-memory lifecycle и persisted task state синхронизированы.
- Allowlisted filesystem access с canonical path isolation и denylist чувствительных путей.
- Model Router с cloud OpenAI-compatible provider и offline Ollama provider.
- Раздельные Codex/OpenCode runner adapters.
- Scoped memory и durable memory search в PostgreSQL.
- Chat, voice boundary, CosyVoice runtime boundary, perception/learning/proactive/personality foundation.
- CLI HTTP client и минимальные Android-модели.

## Что считать незавершённым

1. Довести persistence и API до цельного поведения для personality, humor, family lore, people и событий; people, humor, personality, family-lore, relationships и events теперь используют typed durable records поверх `tolik_memories`.
2. Сделать task execution полноценным сквозным сценарием с реальным подключённым Agent, прогрессом, cancellation и понятным результатом; lifecycle state transitions, cancellation token linkage, per-step `TaskProgress`, `/tasks/{id}/events`, authenticated Agent heartbeat, stale Agent status/selection guard, correlated bounded command poll/complete transport, authenticated Agent disconnect с cleanup очереди/pending команд, audit events для connect/heartbeat/poll/complete/disconnect, PostgreSQL advisory serialization audit chain, database append-only trigger, allowlisted Agent command handler для read/list/process/build/test/Codex/OpenCode, remote-only dispatch и bounded reconnect/command loop уже добавлены.
3. Завершить интеграцию Codex/OpenCode поверх уже существующего runner слоя.
4. Довести thin clients, voice runtime и подготовку транскрипций CosyVoice до домашнего deployment сценария.
5. После этого переходить к perception, learning/proactive behavior и VPS/home deployment.

## Рекомендуемая следующая вертикаль

Начинать с durable personal context: `people`, `personality`, `humor`, `family-lore` и связанных ownership/privacy правил. Это минимально расширяет существующий API, укрепляет ключевую идею многопользовательской памяти и не требует сразу подключать внешний LLM или Windows execution.

Альтернативная первая вертикаль — task execution через Agent, если приоритетом является демонстрация полного MVP-сценария «запрос → план → выполнение → результат». Следующий крупный слой теперь — полноценный task execution через Agent и запись его lifecycle events.
